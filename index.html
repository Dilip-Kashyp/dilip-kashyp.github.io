01Work · Stryv.ai

Grounded retrieval for compliance automation

An AI module that only accepts an answer it can back with a verbatim quote from the source document.

What I'm building

The AI automation module of a vendor-compliance platform: retrieval, reranking, quote validation and an async approval pipeline, in FastAPI on PostgreSQL with pgvector.

  • Python
  • FastAPI
  • PostgreSQL
  • pgvector
  • Cross-encoder
  • Async pipelines

Engineering decisions

  • Hybrid retrieval. Vectors catch paraphrases. Keyword search catches the exact clause names and numbers that embeddings blur.
  • Rerank before generating. A cross-encoder scores every (question, passage) pair, so the strongest evidence reaches the model first.
  • Verify, then involve a human. A quote that isn't in the source verbatim fails validation. Validated answers still wait for human approval.
Request flow

    Question → keyword search + vector search (pgvector) → cross-encoder rerank → LLM draft with quote → verbatim-quote check → human approval.

    02Side project · Live

    Jugaad Link

    A URL shortener with Redis-cached redirects, password-protected and expiring links, and per-link analytics.

    Live Backend Frontend

    What I built

    A Go (Gin, GORM) API on PostgreSQL and Redis with JWT auth, custom slugs, QR codes, guest sessions, a Chrome extension, and click analytics by device, browser, country and referrer. Next.js frontend.

    • Go
    • Gin
    • GORM
    • PostgreSQL
    • Redis
    • JWT
    • Docker
    • Next.js

    Engineering decisions

    • Cache only plain links. Password, expiry and click-limit rules must run on every visit. Caching those redirects would silently bypass them.
    • Record clicks asynchronously. Analytics never sits on the redirect's critical path.
    • Fail to a friendly page. Disabled, expired and over-limit links redirect to an explanation instead of a bare error.
    Request flow

      Browser → Gin API → Redis (hit: 302 redirect) or PostgreSQL (miss: rule checks, 302, then cache).

      03Side project

      Atlas

      A multi-tenant Slack and GitHub assistant: OAuth 2.0, per-workspace webhooks, and a Gemini agent that calls tools.

      Code

      What I built

      A FastAPI modular monolith with a Next.js 15 dashboard: OAuth 2.0 login (Google, GitHub, Slack), organization and workspace tenancy, per-tenant webhook ingestion, and a Gemini orchestrator with function calling and a tool dispatcher. PostgreSQL via async SQLAlchemy and Alembic.

      • Python
      • FastAPI
      • SQLAlchemy
      • PostgreSQL
      • Redis
      • Gemini
      • OAuth 2.0
      • Next.js

      Engineering decisions

      • Encrypt provider tokens at rest. Slack and GitHub tokens are Fernet-encrypted in PostgreSQL and decrypted only for the tenant that sent the event.
      • Rotate refresh tokens. They're stored hashed, rotated on every refresh and kept in HTTP-only cookies.
      • Modular monolith first. One deployable with clear module boundaries (auth, integrations, orchestrator), to split only when scale asks for it.
      Request flow

        Slack event → FastAPI → tenant lookup and token decryption in PostgreSQL → Gemini function call → GitHub tool → reply in thread.
